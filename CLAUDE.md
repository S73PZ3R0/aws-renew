This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Build binary for current platform (also regenerates CHECKSUM.asc)
make build

# Run all tests
make test

# Run a single test package
go test -v ./internal/updater/...

# Run a single test function
go test -v -run TestFunctionName ./internal/aws/...

# Install to GOPATH/bin
make install

# Build multi-platform snapshots (requires goreleaser)
make snapshot

# Regenerate CHECKSUM.asc from source files
make checksum

# Verify binary integrity
make verify

# Create a production release (requires goreleaser + GPG key)
make release
```

## Architecture

The tool has three operating modes, all sharing the same core update pipeline:

1. **Interactive TUI** (default) — Bubble Tea orchestrator with a multi-step flow: IP detection → region scan → instance list → `ui.RunInstanceSelector` → `ui.RunRuleSelector`/`ui.RunPortSelector` → `ui.NewExecModel` (live progress monitor)
2. **Batch/headless** (`--batch`) — same pipeline, no TUI, JSON output to stdout
3. **Daemon** (`--daemon` / `service` subcommand) — `daemon.Daemon` polls on `poll_interval`, calls the same `updater.SSHRuleUpdater.Update` on IP change

### Core update logic (`internal/updater/updater.go`)

`SSHRuleUpdater.Update` manages security group rules by **description tag**: it only touches ingress TCP rules whose `Description` matches the configured `rule_description`. Rules without that description are never modified. The `--cleanup` flag enables a second pass that revokes any managed-description rules for ports not in the current target set.

### AWS layer (`internal/aws/aws.go`)

`NewClient` uses the standard AWS credential chain but will prefer `AWS_ACCESS_KEY_ID` env vars when set (injected by the interactive credential prompt in `main.go:promptCredentials`). Auth errors and config errors are wrapped in typed sentinels (`AWSAuthError`, `AWSConfigError`) so `main.go:isAuthErr` can trigger the credential fallback loop.

### Config resolution order

CLI flags > `config.yaml` values > compiled defaults. Config lives at `~/.config/aws-renew/config.yaml`. `loadCfg()` in `main.go` merges them.

### Notification (`internal/notify/notify.go`)

`Notifier.Send` fans out to all configured channels (generic webhook, Telegram, Discord, Slack) when rules are updated or revoked. Notifications are fire-and-forget — errors are logged but never fatal.

### Integrity / self-update

- `CHECKSUM.asc` is a plain SHA-256 manifest of source files, regenerated by `make checksum` on every build. It is **not** a PGP-armored file despite the `.asc` extension — the GPG signature is overlaid separately.
- `verifier.VerifySignature` shells out to `gpg --verify`; missing `gpg` returns a `SignatureError` not a hard failure.
- `selfupdate` downloads a GitHub release asset, extracts to a sandbox, calls `verifier.VerifyFiles(sandboxDir)`, then applies via `go-update`.

### Service management (`internal/svcmgr/svcmgr.go`)

`kardianos/service` wraps systemd/launchd/Windows SCM. On Termux (`TERMUX_VERSION` env var), all `service` subcommands return a user-friendly error directing to `--daemon` instead.

### UI package (`internal/ui/`)

- `theme.go` — lipgloss color/style constants shared everywhere
- `orchestrator.go` — stateless panel renderers (Header, EnvPanel, DiscoveryTree, SummaryPanel, etc.)
- `execview.go` — Bubble Tea model for the live PROCESS_MONITOR panel
- `selector.go` — Bubble Tea model for instance/port/rule selection
- `input.go` — `ReadPassword` (masked terminal input)
